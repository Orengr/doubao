## 为什么之前"看起来成功"

1. **recent_conv 返回 1 个空会话** = 无效 session 时豆包返回游客空数据，不是"登录成功"
2. **get_web_anon_id 返回 uid** = anon_id 是匿名 ID，不是登录身份
3. **HARD 证据**：config/pull（用户配置接口）对所有 4 个 cookie 文件全部返回 `710012001 登录已过期`
4. ka_pure 的 send_and_get_reply 不校验异常 → 空回复也算"✅ 已发出"

## 为什么 cookie 死这么快

豆包 passport 是**单点会话**：同一账号每次短信登录都会顶掉上一个 web session。
今天登录了 4 次（07:33/08:07/08:26/09:51），每次都把前一个顶掉。最后 09:51 的 combo2 session 也死了（可能 11:53 还有过一次登录尝试或风控清除）。

## 手机能看到 vs API 看不到

你手机 app 的 7 个会话（主对话/运行ensure.sh脚本/...）+ 置顶"主对话" + 账号"小777" = 真实账号视图。
API 侧全部看不到 = API 侧从未真正登录过。两个世界完全隔离。

## 现在怎么办（正确路径）

1. **一次登录，只登录一次**，之后绝不再发验证码/不再登录（否则前功尽弃）
2. 登录后立刻把 cookie 存好 + **用 config/pull 验证真登录**（code=0 才算数）
3. ka_pure 改成：先用 config/pull 检活再发消息，session 失效就停+报警，不空转
4. 消息发送带 conversation_id（修复版 ka_pure.py 已在服务器上）

## 登录方式选择

- 短信登录（sms_auto.py，浏览器方式）——已验证可工作，但需要你提供新验证码
- 纯接口登录（direct_sms.py + sms_login）——算法已全破（XOR 0x05，mobile="+86 18..." 14字节，code 6位），sms_login 提交需要 passport 域 cookie 前置 + sign 参数（抓包里有完整参数模板）
