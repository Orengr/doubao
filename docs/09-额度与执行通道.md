# 如何避免豆包额度不足（关键）

## 核心原则

**不要让豆包在对话里跑长任务。** 豆包对话每次都有额度/时长限制，装环境这种几分钟的任务很容易跑一半断掉。

## 正确做法：走控制面接口执行

面板已内置执行通道，**完全绕过对话额度**：

```bash
# 服务器上发一条命令到沙箱（不消耗对话额度）
curl -s -X POST "http://127.0.0.1:17800/sh?token=<TOKEN>" --data-raw '你的命令'

# 或者用面板 API
curl -s "http://127.0.0.1:18800/api/sbx?cmd=你的命令"

# 长任务用后台（立即返回，进程独立存活）
curl -s -G "http://127.0.0.1:18800/api/sbx" \
  --data-urlencode "cmd64=$(echo '你的长命令' | base64 -w0)"
```

## 长任务必须后台跑

```bash
setsid nohup sh /path/to/long_task.sh > /tmp/task.log 2>&1 < /dev/null &
```

- `setsid` 让进程脱离终端
- `nohup` 忽略挂起信号
- `< /dev/null` 断开标准输入
- 之后用 `tail -f /tmp/task.log` 看进度（也是走控制面，不耗额度）

## 判断任务是否还在跑

```bash
ps -eo pid,comm,args | grep 你的脚本名
```

## 被平台拦截怎么办

豆包对话里如果出现「检测到高风险行为，已终止会话」：
1. **不要在对话里重试**
2. 改用控制面接口执行（上面的命令）
3. 命令拆小步，一步一条

## 额度分配建议

| 用途 | 走哪里 |
|---|---|
| 装环境/编译/解压大包 | 控制面 `/sh` |
| 日常运维（看日志、重启服务） | 面板 UI 或控制面 |
| 与豆包对话聊天 | 豆包会话 |
| 保活小任务 | ka_pure 自动发（60-90秒） |

## 保活与额度的关系

保活小任务会消耗少量豆包额度（每条是一次消息）。所以：
- 间隔 **60-90 秒**：够维持活跃，又不会太费
- 如果额度紧张，可调大到 120-180 秒（改 `ka_pure.py` 的 `random.randint`）
- 隧道维护用 `tunnel_watch`，**不消耗额度**（本地探测 + 只在断时发一条）

## 关键提醒

- **控制面 token 存在** `/home/user/.dsh_pend/state/token.txt`（沙箱内），服务器副本在 `/root/sbx_token.txt`
- 走了控制面就**不会有额度问题**，额度只影响「豆包对话」和「保活消息」
